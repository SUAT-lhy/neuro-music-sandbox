### 二、 第二阶段（升级 PyTorch 神经网络 / RL 生成器）：摩尔线程 vs N卡/A卡 的核心差异

当你下一步开始用 PyTorch 训练 **主旋律+和弦的 Transformer 生成器** 或 **深度神经网络打分器（MLP / 1D-CNN）** 时，才会真正调用摩尔线程的 GPU。

#### 1. 为什么模型权重（`.pt` / `.safetensors`）天生跨平台兼容？
无论是摩尔线程的 **MUSA（`torch_musa`）**、英伟达的 **CUDA**，还是 AMD 的 **ROCm**，它们在 PyTorch 里只是底层的**算子加速后端（Backend）**。
神经网络训练出来的权重参数（`state_dict`）本质上只是一堆标准的 **IEEE 754 浮点数矩阵（FP32 / FP16）**。只要把权重先拉回 `cpu` 再保存，拿到任何显卡上都能直接加载。

#### 2. 唯一会导致后期 N卡/A卡 报错的 3 个坑（及避坑规范）

为了让你的代码在摩尔线程、N卡、A卡之间实现**“一行代码不用改，直接无缝切换”**，请让你的 Coding Agent 严格遵守以下 3 条规范：

##### 规范 ①：使用硬件无关的动态 `device` 路由器（严禁写死 `.cuda()`）
摩尔线程在 PyTorch 中的设备名称叫 `"musa"`（需要 `import torch_musa`），而 N卡和 A卡（ROCm）都叫 `"cuda"`。如果代码里写死 `x.cuda()`，换卡必崩。

请让你的 Coding Agent 在所有 PyTorch 代码开头加入这段**全平台通用设备检测器**：

```python
import torch

def get_universal_device():
    """
    自动兼容：摩尔线程 (MUSA) / 英伟达 (CUDA) / AMD (ROCm) / 苹果 (MPS) / CPU
    """
    # 1. 优先检测摩尔线程 MUSA 环境
    try:
        import torch_musa
        if torch.musa.is_available():
            print("🚀 当前使用显卡：摩尔线程 (Moore Threads MUSA)")
            return torch.device("musa")
    except ImportError:
        pass

    # 2. 检测 NVIDIA (CUDA) 或 AMD (ROCm 伪装为 cuda 接口)
    if torch.cuda.is_available():
        device_name = torch.cuda.get_device_name(0)
        print(f"🚀 当前使用显卡：NVIDIA / AMD ({device_name})")
        return torch.device("cuda")

    # 3. 检测 Apple Silicon (M1/M2/M3/M4)
    if hasattr(torch.backends, "mps") and torch.backends.mps.is_available():
        print("🚀 当前使用显卡：Apple MPS")
        return torch.device("mps")

    print("⚠️ 未检测到加速卡，回退至 CPU")
    return torch.device("cpu")

DEVICE = get_universal_device()
```

##### 规范 ②：保存与加载权重时，强制中转到 `cpu` 并优先使用 `safetensors`
**千万不要**直接把还在 `"musa"` 显存里的模型直接 `torch.save(model, 'model.pt')`！如果直接保存整个模型对象，文件里会硬编码带上 `musa:0` 的设备标签，后期你放到一台没有装 `torch_musa` 驱动的 N卡/A卡机器上执行 `torch.load()` 时，会直接报 `RuntimeError: UntypedStorage ... musa device not found`。

**正确的跨卡保存与加载写法（100% 兼容所有显卡）：**

```python
# ✅ 保存时（在摩尔线程上训练完）：先把 state_dict 转回纯 CPU 内存再存
cpu_state_dict = {k: v.cpu() for k, v in model.state_dict().items()}
torch.save(cpu_state_dict, "music_generator_weights.pt")

# ✅ 加载时（未来在 N卡 / A卡 / 摩尔线程 任意机器上）：
state_dict = torch.load("music_generator_weights.pt", map_location="cpu", weights_only=True)
model.load_state_dict(state_dict)
model.to(DEVICE)  # 再动态挂载到当前机器的显卡上
```

##### 规范 ③：算子与精度避坑（针对摩尔线程硬件特性）
1. **精度选择（优先用 `FP32` 或 `FP16`，慎用 `BF16`）：**
   符号音乐生成模型的参数量通常很小（几百万到几千万参数，远小于大语言模型），在摩尔线程显卡上直接用默认的 **`FP32`（单精度）** 训练不仅速度极快，而且数值最稳定。如果用混合精度，部分摩尔线程消费级显卡（如 S80）对 `bfloat16` 支持不如企业级卡（S4000）完善，建议统一用 `FP32`。
2. **不要用绑定特定显卡的第三方 C++ 算子库：**
   写音乐 Transformer 时，直接用 PyTorch 原生自带的 `torch.nn.MultiheadAttention` 或 `F.scaled_dot_product_attention`，**不要强行依赖** `flash-attn`、`xformers` 或 `bitsandbytes`。因为后面这几个库深度绑定了英伟达私有的 CUDA PTX 汇编指令，在摩尔线程和部分 A卡上编译会非常痛苦，而原生 PyTorch 算子在摩尔线程 `torch_musa`、N卡、A卡上全都原生支持。
